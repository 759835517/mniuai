# MNIU AI Camp - PRD 优化与补充分析

> 基于第一版PRD的全面审查，以下列出需要优化和补充的关键领域。

---

## 一、PRD 现有问题分析

### 1. 安全与权限体系缺失

**问题**：PRD 仅提到 JWT 认证，但缺少以下关键内容：
- 未定义角色体系（管理员 vs 普通用户）
- 未说明管理员如何管理成就定义、查看全局数据
- AI Prompt 注入防护仅一句带过，缺少具体策略
- 未提及 API 限流（Rate Limiting）策略，AI 调用成本高昂，必须限制

**建议补充**：
- 增加 RBAC 角色模型：`ADMIN` / `USER`
- 定义 API 限流规则（如：AI 教练每日 100 次调用，路线图生成每日 5 次）
- Prompt 安全：用户输入过滤 + 系统提示词防泄露 + 输出内容安全审核

### 2. AI 服务可靠性与降级策略

**问题**：
- 未说明 AI 服务（Qwen）不可用时的用户体验
- 重试机制仅提到"最多2次"，缺少指数退避、超时设置
- 流式响应中断如何处理未定义

**建议补充**：
- 定义超时：首字超时 5s，整体超时 60s
- 降级策略：AI 不可用时展示友好提示 + 缓存最近一次成功结果
- 流式断线重连机制（前端 SSE 自动重试）

### 3. 成长体系细节不足

**问题**：
- 等级定义缺失：总共多少级？每级需要多少 XP？
- 成就仅提到"可选"，缺少具体的成就列表
- 打卡规则不明确：什么算"完成学习活动"？时长阈值？
- 成就的 `criteria_json` 格式未定义

**建议补充**：
- 明确等级表（建议 50 级，每 5 级一个段位标签）
- MVP 至少定义 10 个核心成就
- 打卡规则：当日完成任意 1 个学习活动（≥10分钟）即为打卡
- 定义 `criteria_json` 的 JSON Schema

### 4. 学习路线图的迭代逻辑

**问题**：
- "重新生成"仅说保留历史，但未说明新旧路线图如何对比
- 用户中途调整目标后，已有进度如何迁移
- 路线图中的"推荐项目"与项目教练模块的关系不明确

**建议补充**：
- 路线图版本管理：支持查看不同版本差异
- 进度继承：重新生成时已完成的任务标记保留
- 推荐项目点击后跳转到项目教练，自动填充上下文

### 5. 代码审查模块范围

**问题**：
- 仅提到"公共 GitHub 仓库"，未说明支持的文件类型和大小限制
- 仓库"过大"的阈值未定义
- 代码片段支持的语言未列举
- 审查结果的评分标准不明确

**建议补充**：
- 单次审查最大 50 个文件，单文件最大 500KB
- 仓库分析：自动识别主要语言目录，排除 node_modules / vendor 等
- 审查维度评分：安全性 / 可维护性 / 性能 / AI 最佳实践（各 10 分）
- 支持的代码片段语言：Java, Python, TypeScript, JavaScript, Go

### 6. 缺失的关键功能

| 缺失功能 | 重要性 | 说明 |
|----------|--------|------|
| 通知系统 | 高 | 学习提醒（每日定时）、成就解锁通知、路线图更新通知 |
| 数据导出 | 中 | 用户导出学习数据（GDPR 合规要求） |
| 搜索功能 | 中 | 搜索历史对话、审查记录、项目列表 |
| 分享功能 | 低 | 分享学习成就到社交媒体 |
| 国际化 | 低 | MVP 阶段仅中文，但应预留 i18n 架构 |
| 埋点分析 | 高 | 用户行为追踪，产品迭代的数据基础 |

### 7. 会话与上下文管理

**问题**：
- "最近 N 条消息"的 N 未确定
- 未说明 Token 预算管理
- 教练对话是否有主题/上下文切换机制

**建议补充**：
- 默认携带最近 10 轮消息（约 4K Token）
- 用户可手动"清除上下文"开启新话题
- 超出 Token 限制时，采用滑动窗口 + 系统提示词压缩策略

### 8. 环境与部署

**问题**：
- 仅提到 Vercel + Railway，缺少本地开发环境说明
- 数据库迁移策略未提及
- CI/CD 流程未定义
- 监控告警方案缺失

**建议补充**：
- 本地开发：Docker Compose（PostgreSQL + Redis + 后端 + 前端）
- 数据库迁移：Flyway（Spring Boot 生态标准）
- CI/CD：GitHub Actions
- 监控：Spring Boot Actuator + 日志聚合

## 二、数据模型补充建议

### 补充表

| 表名 | 说明 |
|------|------|
| `user_roles` | 用户角色关联（RBAC） |
| `notifications` | 系统通知 |
| `api_usage_log` | API 调用日志（限流+统计） |
| `user_settings` | 用户偏好设置（语言、通知开关等） |
| `learning_progress` | 路线图中每周的详细学习进度 |
| `review_comments` | 代码审查的具体行级评论 |

### 需要修改的表

- `users`：增加 `avatar_url`, `nickname`, `status`(ACTIVE/BANNED)
- `code_reviews`：增加 `score_json`（各维度评分）、`file_count`
- `achievements`：明确 `criteria_json` 的 Schema 定义
- `projects`：增加 `description`, `tech_stack_json`

## 三、API 设计补充建议

### 缺失的端点

- `GET /notifications` / `PUT /notifications/{id}/read` — 通知管理
- `GET /users/me` / `PUT /users/me` — 用户个人信息管理
- `GET /admin/stats` — 管理员数据统计（可选）
- `POST /coach/sessions/{id}/clear` — 清除对话上下文
- `GET /search` — 全局搜索

### 限流策略

| 端点组 | 限流规则 |
|--------|---------|
| AI Coach 消息 | 100 次/天/用户 |
| 路线图生成 | 5 次/天/用户 |
| 项目生成 | 10 次/天/用户 |
| 代码审查 | 20 次/天/用户 |
| 普通 CRUD API | 60 次/分钟/用户 |

## 四、非功能性需求补充

| 维度 | 补充内容 |
|------|---------|
| 安全 | HTTPS 强制、CORS 白名单、CSRF 防护、SQL 注入防护、XSS 过滤 |
| 可观测性 | 请求链路追踪（Trace ID）、AI 调用耗时监控、错误率告警 |
| 数据备份 | PostgreSQL 每日自动备份，保留 30 天 |
| 合规 | 用户可删除账户和所有数据（GDPR right to erasure） |
| 兼容性 | Chrome/Firefox/Safari 最新版，移动端自适应（非原生 App） |
