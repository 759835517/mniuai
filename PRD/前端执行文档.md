# MNIU AI Camp 前端开发执行文档

版本：1.0  
目标前端：Next.js 14 App Router + TypeScript + TailwindCSS + shadcn/ui  
设计风格：暗色主题，参考 Cursor / Windsurf 的高密度 AI 开发工具界面  
后端基础路径：`/api/v1`  
读者：前端工程师、AI Agent、UI 工程师、测试工程师

---

## 0. 产品目标与前端边界

MNIU AI Camp 是面向转型 AI 工程的开发者的 AI 原生学习平台。前端必须提供一个完整、可交互、工程感明确的学习工作台，而不是营销展示站。核心体验包括：

1. AI 学习路线图：用户输入技能、目标、可用时间，生成路线图并以时间轴展示，支持任务进度更新。
2. AI 编程教练：类 ChatGPT 对话体验，支持 Markdown、代码高亮、SSE 流式输出、历史会话。
3. AI 项目教练：项目类型选择、AI 生成项目计划、任务看板、Mermaid 架构图、代码模板展示。
4. AI 代码审查：GitHub URL 或代码片段输入，Monaco Editor 编辑与 diff 展示，结构化审查结果。
5. 成长体系：XP、等级、打卡、统计图表、成就墙、活动时间线、通知。

前端边界：

- 前端只负责展示、交互、状态管理、API 调用和少量 BFF 代理。
- AI 生成、权限校验、成长结算、成就解锁由后端负责。
- 前端可以使用 Vercel AI SDK 作为未来 BFF 扩展，但第一版主要消费后端 SSE。
- Token 存储第一版采用 `localStorage` + axios 拦截器；若后端后续支持 HttpOnly Cookie，应迁移到 Cookie 模式。

## 1. 项目初始化与配置

### 1.1 create-next-app 命令

在 `D:\IdeaProjects\mniuai\front-end` 下初始化：

```bash
npx create-next-app@14.2.35 front-end \
  --typescript \
  --tailwind \
  --eslint \
  --app \
  --src-dir \
  --import-alias "@/*" \
  --use-npm
```

如果目录已存在且为空，可进入该目录执行：

```bash
npx create-next-app@14.2.35 . \
  --typescript \
  --tailwind \
  --eslint \
  --app \
  --src-dir \
  --import-alias "@/*" \
  --use-npm
```

运行环境要求：

```text
Node.js >= 18.18.0，当前开发环境使用 24.14.1；CI/生产建议固定 20.19.x LTS 或 24.14.1，避免不同机器 Node 大版本漂移
npm >= 10.0.0
Next.js = 14.2.35
React = 18.3.1
TypeScript = 5.9.3
TailwindCSS = 3.4.19
```

### 1.5 next.config.js

```js
/** @type {import('next').NextConfig} */
const nextConfig = {
  reactStrictMode: true,
  poweredByHeader: false,
  compress: true,
  experimental: {
    typedRoutes: false
  },
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: '**'
      }
    ]
  },
  async rewrites() {
    const apiUrl = process.env.NEXT_PUBLIC_API_URL || 'http://localhost:8080';
    return [
      {
        source: '/api/backend/:path*',
        destination: `${apiUrl}/api/v1/:path*`
      }
    ];
  },
  webpack(config) {
    config.resolve.fallback = {
      ...config.resolve.fallback,
      fs: false,
      path: false
    };
    return config;
  }
};

export default nextConfig;
```

说明：

- 浏览器端 API 调用推荐走 `/api/backend`，由 Next rewrites 代理到后端，减少 CORS 问题。
- 如果部署平台直接配置反向代理，也可以设置 `NEXT_PUBLIC_API_BASE_PATH=/api/v1`。
- Monaco、Mermaid 等重型组件必须动态导入，避免影响首屏。

## 4. API 客户端与拦截器设计

### 4.1 axios 实例 `src/lib/api/client.ts`

核心要求：

- `baseURL` 使用 `NEXT_PUBLIC_API_BASE_PATH`，默认 `/api/backend`。
- 请求拦截器自动附加 access token。
- 响应拦截器统一 unwrap `data`。
- 401 时自动 refresh token。
- refresh 并发时只发起一个 refresh 请求，其余请求等待。
- refresh 失败后清理本地登录态并跳转 `/login`。

实现骨架：

```ts
import axios, { AxiosError, type InternalAxiosRequestConfig } from 'axios';
import type { ApiResponse } from '@/lib/types/api';
import { tokenStorage } from '@/lib/utils/tokenStorage';

const baseURL = process.env.NEXT_PUBLIC_API_BASE_PATH || '/api/backend';

export const apiClient = axios.create({
  baseURL,
  timeout: 30000,
  headers: {
    'Content-Type': 'application/json'
  }
});

let refreshPromise: Promise<string | null> | null = null;

apiClient.interceptors.request.use((config: InternalAxiosRequestConfig) => {
  const token = tokenStorage.getAccessToken();
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

apiClient.interceptors.response.use(
  (response) => {
    const body = response.data as ApiResponse<unknown>;
    if (typeof body?.code === 'number' && body.code !== 200) {
      return Promise.reject(new Error(body.message || '请求失败'));
    }
    return body?.data ?? response.data;
  },
  async (error: AxiosError) => {
    const original = error.config as (InternalAxiosRequestConfig & { _retry?: boolean }) | undefined;

    if (error.response?.status === 401 && original && !original._retry) {
      original._retry = true;

      if (!refreshPromise) {
        refreshPromise = refreshAccessToken().finally(() => {
          refreshPromise = null;
        });
      }

      const newToken = await refreshPromise;
      if (newToken) {
        original.headers.Authorization = `Bearer ${newToken}`;
        return apiClient(original);
      }
    }

    const message = extractApiErrorMessage(error);
    return Promise.reject(new Error(message));
  }
);

async function refreshAccessToken(): Promise<string | null> {
  const refreshToken = tokenStorage.getRefreshToken();
  if (!refreshToken) return null;

  try {
    const response = await axios.post<ApiResponse<{ accessToken: string; refreshToken?: string }>>(
      `${baseURL}/auth/refresh`,
      { refresh_token: refreshToken, refreshToken }
    );
    const token = response.data.data.accessToken;
    tokenStorage.setAccessToken(token);
    if (response.data.data.refreshToken) {
      tokenStorage.setRefreshToken(response.data.data.refreshToken);
    }
    return token;
  } catch {
    tokenStorage.clear();
    if (typeof window !== 'undefined') {
      window.location.href = '/login';
    }
    return null;
  }
}

function extractApiErrorMessage(error: AxiosError): string {
  const data = error.response?.data as { message?: string } | undefined;
  return data?.message || error.message || '网络请求失败';
}
```

### 4.4 SSE 连接管理

后端 `POST /coach/sessions/{id}/messages` 是 SSE 流式响应。浏览器原生 `EventSource` 不支持 POST body，因此第一版使用 `fetch` + ReadableStream 解析 SSE。

`useSSE.ts` 行为：

- 接收 URL、body、headers。
- 使用 `AbortController` 支持停止生成。
- 解析 `event:` 与 `data:`。
- 按事件名调用 `onToken`、`onDone`、`onError`。
- 组件卸载时自动 abort。

实现骨架：

```ts
export interface SsePostOptions {
  url: string;
  body: unknown;
  headers?: Record<string, string>;
  onToken: (delta: string) => void;
  onDone: (payload: unknown) => void;
  onError: (error: Error) => void;
}

export async function postSse(options: SsePostOptions): Promise<AbortController> {
  const controller = new AbortController();
  const token = tokenStorage.getAccessToken();

  const response = await fetch(options.url, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Accept: 'text/event-stream',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...options.headers
    },
    body: JSON.stringify(options.body),
    signal: controller.signal
  });

  if (!response.ok || !response.body) {
    throw new Error(`SSE 请求失败：${response.status}`);
  }

  const reader = response.body.getReader();
  const decoder = new TextDecoder('utf-8');
  let buffer = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const chunks = buffer.split('\n\n');
    buffer = chunks.pop() ?? '';

    for (const chunk of chunks) {
      const event = parseSseChunk(chunk);
      if (event.type === 'token') {
        options.onToken(String(event.data.delta ?? ''));
      } else if (event.type === 'done') {
        options.onDone(event.data);
      } else if (event.type === 'error') {
        options.onError(new Error(event.data.message || 'AI 响应失败'));
      }
    }
  }

  return controller;
}
```

## 5. 状态管理设计 Zustand

### 5.1 总体原则

- Store 只保存跨页面共享状态。
- 单页面临时表单状态使用 `react-hook-form`。
- API loading/error 必须在 store 或 hook 中显式建模。
- Store action 内部捕获异常，写入 `error`，同时抛出给 UI 选择 toast。
- 不在组件中直接写 `localStorage`，统一走 `authStore` 和 `tokenStorage`。

### 6.2 middleware 实现策略

由于第一版 token 存储在 `localStorage`，middleware 无法读取。可选方案：

1. 第一版 middleware 只处理简单路径白名单，不做强校验。
2. 实际认证保护由 `AuthGuard` 在客户端执行。
3. 后续迁移 HttpOnly Cookie 后，在 middleware 中读取 access token cookie 并验证。

实现：

```ts
import { NextResponse, type NextRequest } from 'next/server';

const publicRoutes = ['/', '/login', '/register'];

export function middleware(request: NextRequest) {
  const { pathname } = request.nextUrl;

  if (
    pathname.startsWith('/_next') ||
    pathname.startsWith('/api') ||
    pathname.startsWith('/images') ||
    pathname === '/favicon.ico'
  ) {
    return NextResponse.next();
  }

  const isPublic = publicRoutes.includes(pathname);
  const tokenCookie = request.cookies.get('mniu_access_token')?.value;

  if (!isPublic && tokenCookie === '') {
    const loginUrl = new URL('/login', request.url);
    loginUrl.searchParams.set('redirect', pathname);
    return NextResponse.redirect(loginUrl);
  }

  return NextResponse.next();
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico).*)']
};
```

### 6.3 AuthGuard

`AuthGuard` 是第一版实际生效的保护层：

- dashboard layout 挂载。
- 调用 `authStore.hydrateFromStorage()`。
- 有 token 但无 user 时调用 `fetchMe()`。
- 无 token 时跳转 `/login?redirect=<current>`.
- loading 时显示全屏骨架。

## 19. 开发规范

### 19.1 文件命名

- React 组件：PascalCase，例如 `ChatInterface.tsx`。
- Hook：camelCase 且 `use` 开头，例如 `useChat.ts`。
- Store：camelCase，例如 `authStore.ts`。
- API 文件：camelCase，例如 `roadmap.ts`。
- 类型文件：camelCase 或领域名，例如 `growth.ts`。
- CSS class：Tailwind utility 优先；自定义 class 用 kebab-case。

### 19.2 导出规范

- 组件默认导出。
- Props 类型具名导出。
- 工具函数具名导出。
- Store hook 具名导出。

示例：

```ts
export interface XPBarProps {}
export default function XPBar(props: XPBarProps) {}
```

### 19.3 TypeScript

- 禁止使用 `any`。
- 不确定数据用 `unknown` 并做类型收窄。
- API 响应必须定义类型。
- 组件 props 必须显式定义。
- 不使用隐式 `children`，需要 children 时显式声明。

### 19.4 CSS

- 优先 TailwindCSS utility classes。
- 重复样式用组件封装，不急于抽全局 CSS。
- 复杂滚动条、Markdown 排版可放 `globals.css` component layer。
- 不使用内联 style，除非动态数值很难 Tailwind 化。

### 19.5 可访问性

- 所有 icon button 必须有 `aria-label` 或 Tooltip。
- 表单 input 绑定 label。
- Dialog 有 title。
- 键盘可操作：Tab 顺序合理，Esc 关闭弹窗。
- 颜色状态不能只靠颜色，必须有文字或图标。

### 19.6 日志

前端不记录：

- password
- access token
- refresh token
- 大段用户代码
- AI 原文长内容

开发环境可记录：

- API endpoint
- status
- duration
- store action 名称

### 24.5 统一响应格式


前端 `client.ts` 响应拦截器处理：

1. 提取 `response.data` 得到 `ApiResponse<T>`。
2. 检查 `body.code !== 200`（业务码非 200），reject。
3. 否则返回 `body.data`（组件只消费 data）。

分页响应：


### 24.7 SSE 对接协议

端点：`POST /coach/sessions/{id}/messages`

Content-Type：`text/event-stream`

前端发送：

```ts
fetch(url, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Accept': 'text/event-stream',
    'Authorization': `Bearer ${token}`
  },
  body: JSON.stringify({ content: "用户消息" }),
  signal: abortController.signal
})
```

后端必须确保：

1. 响应头 `Content-Type: text/event-stream`。
2. 响应头 `Cache-Control: no-cache`。
3. 每个事件以 `\n\n` 分隔。
4. 格式为 `event: {type}\ndata: {json}\n\n`。
5. 流结束时发送 `event: done` 后关闭连接。

前端解析：

1. 使用 `ReadableStream` 读取 chunk。
2. 按 `\n\n` 分割得到事件块。
3. 解析 `event:` 行得到类型（token/done/error）。
4. 解析 `data:` 行得到 JSON。
5. `token` 事件：append delta 到当前消息。
6. `done` 事件：保存 messageId，标记完成。
7. `error` 事件：标记失败，显示错误。

### 24.8 认证对接

Token 传递：

```text
Authorization: Bearer {accessToken}
```

前端存储位置：`localStorage` key `mniu_access_token` / `mniu_refresh_token`

Refresh 流程：

1. 后端返回 401。
2. 前端 `client.ts` 拦截器捕获。
3. 使用 `refreshToken` 调用 `POST /auth/refresh`。
4. 后端校验 refresh token → 删除旧 token → 写入新 token → 返回新 token 对。
5. 前端更新 localStorage → 重试原请求。
6. 并发 401 时只发一次 refresh（`refreshPromise` 单例）。
7. refresh 失败 → 清除 localStorage → 跳转 `/login`。

| 现象 | 可能原因 | 排查步骤 |

## 25. 后续扩展预案

### 25.1 从 localStorage token 迁移到 Cookie

后端支持 HttpOnly refresh cookie 后：

- access token 可只放内存。
- refresh token 放 HttpOnly Cookie。
- middleware 可读 cookie 做服务端重定向。
- axios refresh 不再读取 localStorage refresh token。

### 25.2 引入 React Query

当前使用 Zustand 管理服务端状态。后续数据复杂后可引入 TanStack Query：

- API 缓存。
- 自动重试。
- staleTime。
- optimistic updates。

迁移原则：

- auth 和 UI 仍用 Zustand。
- 服务端列表和详情迁移到 Query。

### 25.3 实时通知

第一版轮询 unread count。

后续可选：

- SSE `/notifications/stream`
- WebSocket
- Server Push

### 25.4 多主题

第一版默认 dark。

后续支持：

- dark
- light
- system

设计 token 已用 CSS variables，可以扩展 light theme。
