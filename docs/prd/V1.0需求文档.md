# 模块一：视频播放 + 进度记录系统

## 1. 背景与目标

**问题**：当前平台无结构化课程内容，用户进来只有AI 对话，无法形成系统学习路径。且对赌退款协议需要客观的"有效学习时长"数据，依赖此模块采集。

**目标**：
- 提供章节视频播放能力，支持断点续播
- 采集有效播放时长（防倍速作弊、防跳进度）
- 解锁机制：章节测验通过后解锁下一章
- 为对赌审核提供可信学习记录

## 3. 防作弊设计（对赌核心）

| 风险 | 防护策略 |
|---|---|
| 视频倍速播放 | `speed > 2.0` 的心跳不计入 `valid_watched_sec` |
| 拖拽进度条跳过 | 心跳间隔内position跳跃 > 30 秒，仅计入实际经过秒数 |
| 静置不看 | 超过 60 秒无心跳上报，暂停计时 |
| 重复刷同一段| 用位图（Redis bitset）记录已覆盖的 5 秒分段，不重复累加 |
| 多标签页刷 | 服务端对同user+lesson 限流：同一秒只接受 1 次心跳 |

**心跳上报规则（前端）**：
- 每**10 秒**上报一次当前 `position_sec` 和 `speed`
- 页面 visibility 切换为 hidden 时立即上报并暂停
- 恢复 visible 时重新开始上报

# 模块二：图文内容 CMS 后台

## 1. 背景与目标

**问题**：课程内容（文章、知识点、操作手册）依赖工程发版，内容团队无法独立运营，内容迭代成本极高。

**目标**：
- 内容团队可在后台独立创建、编辑、发布 Markdown 图文内容
- 支持关联到课程章节、路线图周次、面试题库
- 前台用户可阅读图文，AI 助教可引用文章作为上下文来源

# 模块三：面试训练营 — AI 面试官 + 题库 MVP

## 1. 背景与目标

**问题**：程序员最强付费动机是涨薪跳槽，但平台目前缺乏面试场景。面试训练营是对赌协议的核心产品（学完90 天未拿到 offer退款）。

**目标**：
- 题库：覆盖算法、系统设计、Java/AI八股、行为面试
- AI 面试官：模拟真实面试官提问→ 用户作答 → AI 评分反馈
- 对赌数据：记录模拟面试次数、通过率，供退款审核

## 3. AI 面试官 Prompt 设计

**System Prompt**：
```
你是一名资深技术面试官，正在对候选人进行技术面试。
面试题目：{question_content}
关键考察点：{key_points}
候选人目标岗位：{target_role}

面试规则：
1. 候选人回答后，你要先追问 1-2 个深入问题（模拟真实面试追问）
2. 追问结束后，输出 JSON 格式评分：
{"score": <0-10>,
  "feedback": "总体评价（50字以内）",
  "key_points_hit": {"考察点名称": true/false},
  "follow_up_done": true,
  "improvement": "最重要的一个改进建议"
}
3. 评分要严格，工作 3 年以上候选人满分要求：思路清晰、举例充分、考虑边界
4. 不要透露参考答案，用问题引导候选人自己思考
```

**多轮对话流程**：
```
轮次 1：AI 出题
轮次 2：用户作答
轮次 3：AI 追问（必须追问至少 1 次）
轮次 4：用户回答追问
轮次 5：AI 输出评分 JSON + 口头总结
```
