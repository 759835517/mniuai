## 二、后端接口隔离设计

### 2.1 API 网关路由策略

虽然后端是单体应用，但通过 **API 路径前缀** 实现逻辑隔离：

```
/api/v1/engineer/**# 程序员端专用
/api/v1/kids/**         # 少儿端专用
/api/v1/admin/**        # 运营端专用（需要ADMIN角色）
/api/v1/common/**       # 三端共享（视频、文章、考试基础能力）
```

```sql
ALTER TABLE users ADD COLUMN user_type varchar(20) NOT NULL DEFAULT 'ENGINEER';
-- 值：CHILD / ENGINEER / PARENT / ADMIN

-- 少儿账号关联家长账号
```

**少儿专属表**：

```sql
-- 竞赛题库（少儿专属）

    contenttext NOT NULL,
    input_format    text,
    output_format   text,
    sample_input    text,
    sample_output   text,
    time_limit_ms   int NOT NULL DEFAULT 1000,
    memory_limit_mb int NOT NULL DEFAULT 256,

CREATE TABLE parent_monitor_logs (
    id              bigint PRIMARY KEY,

    daily_minutes   int NOT NULL DEFAULT 0,
    log_date        date NOT NULL,
    activities      jsonb, -- {"video":30, "exam":20, "competition":10}
    created_at      timestamp NOT NULL DEFAULT now(),
    UNIQUE (child_user_id, log_date)
```

## 四、部署架构

### 4.1 域名与路由

```
程序员端：app.mniuai.com       → Vercel Project A
少儿端：  kids.mniuai.com→ Vercel Project B
运营端：  admin.mniuai.com     → Vercel Project C（内网IP白名单）
后端API： api.mniuai.com→ Spring Boot（阿里云ECS）
CDN：     cdn.mniuai.com→ 阿里云OSS
```

### 4.2 Nginx 配置示例

```nginx
# api.mniuai.com
upstream backend {
    server 127.0.0.1:8080;
}

server {
    listen 443 ssl;
    server_name api.mniuai.com;
    
    location /api/v1/engineer/ {
        proxy_pass http://backend;
        # 无特殊限制
    }
    
    location /api/v1/kids/ {
        proxy_pass http://backend;
        # 增加请求频率限制（保护少儿用户）
        limit_req zone=kids_api burst=10;
    }
    
    location /api/v1/admin/ {
        proxy_pass http://backend;
        # IP白名单
        allow 10.0.0.0/8;
        deny all;
    }
}
```

## 五、总结与风险

### 5.1 架构优势

| 优势 | 说明 |
|---|---|
| **用户体验** | 少儿/程序员UI风格完全独立，不互相干扰 |
| **开发效率** | Monorepo 共享组件，避免重复造轮子 |
| **安全隔离** | 运营端独立域名+IP白名单，防止数据泄露 |
| **性能优化** | 各端按需加载，少儿端不加载面试训练营代码 |
| **灰度发布** | 三端独立部署，互不影响 |

### 5.2 技术风险

| 风险 |缓解措施 |
|---|---|
| Monorepo 学习成本 | 采用 Turborepo（官方文档完善） |
| 共享组件版本冲突 | 使用 pnpm workspace +严格版本锁定 |
| API 路由复杂度上升 | 通过 OpenAPI 文档自动生成前端 SDK |
| 三端同时开发资源不足 | 优先级：程序员端 > 运营端 > 少儿端 |
