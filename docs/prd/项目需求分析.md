## 二、当前产品问题（P0/P1/P2）

**P0 —阻断核心学习闭环**
- 无图文和视频内容，用户进来只有AI 对话，没有系统知识供给
- 测验系统 PRD 完成但未开发，路线图完成度纯靠自评，无验证
- 支付和订阅模块缺失，无法商业化

**P1 — 核心价值缺失**
- 只有一类用户（程序员转型），少儿用户群体未覆盖，市场规模受限
- 面试能力培训缺失，程序员最强付费动机未打通
- 对赌协议/退款保障未设计，降低用户购买决策门槛的关键杠杆缺失
- 学习路径无分层，零基础用户与高阶用户体验混用

**P2 — 规模化和运营效率**
- 无内容管理后台，课程迭代依赖工程发版
- 无企业/团队培训模式
- 无讲师生态和UGC 内容机制

## 四、学习形式扩展方案

在现有 AI 对话教练基础上，增加以下三种形式：

### 4.1 图文课程

**适用场景**：概念讲解、知识地图、技术文档阅读  
**内容结构**：
- 每篇 1500-3000 字，配合代码块、架构图（Mermaid 已集成）
- 文末附"小测一下"（接入已有考试系统）
- AI 助教悬浮按钮：对任意段落提问

**技术实现**：内容存Markdown，复用前端已有 `react-markdown` + `rehype-highlight`，后台CMS 管理。

### 4.2 视频课程

**适用场景**：操作演示、代码实战过程、讲师讲解  
**内容结构**：
- 视频时长建议 8-15 分钟/集（控制完课率）
- 视频下方同步显示带时间戳的文字笔记（可搜索）
- 章节设置打点测验（进度锁定：答题通过才解锁下一集）
- AI 助教可引用视频某段时间点内容回答问题

**技术实现**：视频存储用阿里云 OSS + CDN，播放器用 Video.js 或阿里云播放器，字幕走WebVTT。

### 4.3 互动实训（现有核心，强化）

编程沙箱 + AI逐级提示，已有 Monaco Editor 基础，待补充自动评测能力。

## 六、对赌协议设计

### 设计原则

对赌退款是付费转化杠杆，核心是：**让真正认真学但没效果的用户退款，让没认真学的用户无法薅羊毛**。

### 通用学习认证门槛（所有对赌产品共用）

申请退款前必须同时满足：

| 维度 | 门槛要求 | 如何采集 |
|---|---|---|
| 学习时长 | 有效学习时长 ≥ 规定总时长的 80%（视频不可倍速超过 2x，需实际播放记录） | 后端打点记录播放进度 |
| 练习完成率 | 每章节配套练习完成率 ≥ 75% | 练习提交记录 |
| 考试参与率 | 每个模块测验至少参与一次（不要求通过） | 考试记录 |
| AI 助教使用 | 至少使用 AI 助教 20 次提问（说明有主动学习行为） | 对话记录 |
| 综合评测 | 结业综合测评分数 ≥ 60分 | 系统自动评分 |

**防作弊机制**：
- 视频快进检测（播放进度连续跳跃 > 30秒计为无效）
- 练习防复制（代码相似度 > 85% 标记为参考答案抄袭）
- AI 对话记录人工抽检（防止无意义发送刷次数）

### 各产品线专项退款条件

#### 面试训练营 — 「找到工作退款」

**退款成立条件**（全部满足）：

| 条件 | 说明 |
|---|---|
| 通用门槛 | 全部满足 |
| 模拟面试次数 | ≥ 10 次完整模拟面试（AI 面试官或真人Mock） |
| 简历完善 | 通过系统简历评分≥ 70 分 |
| 投递行为 | 在平台填写投递记录 ≥ 20 家（不强制核实，但需声明） |
| 时间窗口 | 结业后 **90 天内** 未收到任何书面 offer |
| 申请截止 | 必须在结业后 **120 天内** 提交退款申请 |

**不适用退款的情形**：
- 目标薪资超出当前能力市场合理范围（如初级开发要求 P7薪资）
- 投递行为集中在非开放期（春招/秋招结束后才开始投）
- 有offer 但主动拒绝（需填写拒绝原因，AI 人工抽检）

**退款比例分档**（非全额退款梯度）：

| 情形 | 退款比例 |
|---|---|
| 完全满足所有条件 | 100% |
| 模拟面试 6-9 次（未达10 次） | 60% |
| 满足门槛但90 天内有意向但未成功 | 50% |

#### 少儿竞赛班 — 「未获竞赛成绩退款」

**退款成立条件**：

| 条件 | 说明 |
|---|---|
| 通用门槛 | 全部满足 |
| 竞赛参与 | 在协议周期内参加至少 1 次平台推荐的认可竞赛 |
| 成绩未达标 | 未获得省级三等奖及以上（全国性竞赛除外，全国奖视为成功） |
| 备注 | 未满足参赛年龄或当期无竞赛举办，退款申请延期至下一届 |

### 退款流程设计

```
用户提交退款申请
    → 系统自动校验通用门槛（5 项数据核查）
        → 不满足：展示缺口项，告知无法申请
        → 满足：进入专项条件核查
            → 自动判断可判断项
            → 人工审核需要核实项（如 offer 真实性）
                → 审核通过：72 小时内原路退款
                → 审核拒绝：给出拒绝理由 + 申诉通道
```

**审核 SLA**：系统自动审核 < 24 小时，人工介入 < 5 个工作日。
